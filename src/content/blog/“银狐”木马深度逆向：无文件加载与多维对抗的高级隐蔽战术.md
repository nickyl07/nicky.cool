## 一、前言

本报告针对一例银狐木马样本进行了深度分析。该攻击活动以钓鱼诱饵作为初始突破口，其核心载荷大量运用了无文件内存加载、白加黑伪装、Restart Manager 强杀杀软、以及多重进程注入与父进程伪造（Spoof PID）等高级防御规避（Defense Evasion）技术。最终目的是将 C2 控制模块注入系统核心进程，实现对受控终端的长期远程控制。

```mermaid

    A["税务/发票类钓鱼入口"] --> B["下载 setup6018.exe"]

    D --> E["释放/加载 Shellcode.dll 与 Akagi64.dll"]
```

### 3.1 初始投递

攻击者使用税务、发票、申报升级等主题作为诱饵，引导受害者下载并执行 `setup6018.exe`。该文件不直接暴露完整远控功能，而是作为下载器从远端拉取伪装为图片的 `bai.png`。

![初始投递](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649548.png)

### 3.2 `bai.png` 内存加载与组件释放

`bai.png` 不是正常图片，而是伪装后缀的 Shellcode，由开源工具 DllToShellCode（killeven/DllToShellCode） 将一个或多个恶意 DLL 转换成位置无关、可直接内存执行的二进制流。Shellcode 在内存中解析并装载后续模块，减少磁盘落地痕迹。后缀改为 .png 伪装，绕过文件类型检测。

![Shellcode 解包](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649549.png)

解包后可见 4 个主要组件：

| 组件 | 作用研判 |
| --- | --- |
| `Shellcode.dll` | 主执行模块，通过导出函数 `hanshu` 进入核心逻辑 |
| `Akagi64.dll` | 疑似 UACMe / Akagi 相关提权组件 |
| `Overwatch.exe` | 原始分析中未观察到后续关键行为，暂列为辅助或冗余组件 |
| `active_desktop_render_x64.dll` | 原始分析中未观察到后续关键行为，暂列为辅助或冗余组件 |

![核心组件](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649550.png)

### 3.3 环境探测与诱饵掩护

`Shellcode.dll` 通过导出函数 `hanshu` 启动主要逻辑。

![hanshu 导出函数](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649551.png)

执行初期会检查当前进程是否处于调试状态，用于提高分析成本。

![反调试检查](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649552.png)

同时，也会判断当前权限是否为管理员权限。

![管理员权限检查](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649554.png)

随后样本调用 `InternetOpenUrlW` 下载并执行正常税务开票软件。这一策略以合法软件为诱饵，起到了极好的行为掩护作用 。

![下载正常税务软件](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649553.png)

### 3.4 权限提升

调用 `Akagi64.dll` 尝试提权，如果提权失败，样本会短暂休眠后退出；如果提权成功，则进入安全产品检测与对抗阶段。

![Akagi64 提权](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649555.png)
### 3.5 杀软对抗

针对 `360tray.exe` 使用 Windows Restart Manager 服务来管理 `360tray.exe` 资源，一旦发现该进程存在便将其强行结束 。

![Restart Manager 对抗 360](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649556.png)

![结束 360 进程](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649557.png)

如果对 `360tray.exe` 的结束逻辑成功，样本会执行 `Inject2Explorer`，把 `bb.jpg`（C2 Shellcode）中的 Shellcode 注入 `explorer.exe`（Windows Shell 进程 / 常驻用户交互进程）。

![Inject2Explorer](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649561.png)

后续，该 Shellcode 会尝试连接攻击者控制的 C2 并进入远控阶段。

如果未能成功结束 360 进程，样本会释放一批后备组件到 C 盘根目录：

- `in64.exe`
- `in.exe`
- `aa.dll`
- `bb.dll`
- `MSNDetourDLL_X64.dll`
- `rundll.dll`

![后备组件释放](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649562.png)

程序随后尝试通过 `in.exe`、`MSNDetourDLL_X64.dll`、`rundll.dll` 加载相关 DLL。若常规加载失败，则退而使用命令行方式强制执行。

![后备 DLL 加载](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649563.png)

在启动新进程时，样本使用 MalSecLogon 思路并结合Spoof PID（父进程欺骗），把新进程的父进程伪装为 `explorer.exe`，以此躲避进程链监控。

(*MalSecLogon是开源工具，用于滥用 Windows Seclogon（Secondary Logon，辅助登录）服务，实现**PPID 欺骗**与**LSASS 进程内存转储**，属于**凭证窃取 / 权限维持**类红队工具。*)

在该后备流程中，`aa.dll` 负责寻找并加载后续 Shellcode。它先尝试从 `\OneDrive\cache` 路径读取 `bb.jpg`：

![aa.dll 读取 bb.jpg](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649564.png)

如果文件读取失败，则转向注册表 `HKEY_CURRENT_USER\Console`，读取此前写入的 `huorong*` 键值数据：

![aa.dll 读取注册表](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649565.png)

获取载荷后，`aa.dll` 仍会尝试将其注入 `explorer.exe` 执行：

![aa.dll 注入 explorer](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649566.png)


### 3.6 载荷暂存

样本会将一段 Shellcode 写入注册表 `HKEY_CURRENT_USER\Console`，键名由 `huorong` 拼接随机值构成。
![注册表写入 Shellcode](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649558.png)

### 3.7 C2模块

样本内部存在 6001 至 6007 等编号化 Shellcode 资源项，每个编号对应一段内嵌 Shellcode 数据。部分 Shellcode 尾部附带明文配置区，可见 6002.baidu787.com 等域名，疑似为后续远控模块使用的 C2 节点。6001/6002 既可能是模块编号，也可能被复用为 C2 子域名分组。
![释放 bb.jpg](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649559.png)

![bb.jpg Shellcode](https://image-hosting-210.oss-cn-beijing.aliyuncs.com/blog/20260308231649560.png)
